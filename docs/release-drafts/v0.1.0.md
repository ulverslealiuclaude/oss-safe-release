# oss-safe-release v0.1.0 GitHub Release Draft

## Title

oss-safe-release v0.1.0

## Summary

Initial public release of `oss-safe-release`, a local-first CLI for open-source maintainers who want deterministic safety checks before merging pull requests or cutting releases.

This release focuses on GitHub Actions, release automation, and common secret hygiene risks. It does not send repository contents to an external service.

## Highlights

- Detects risky GitHub Actions patterns, including mutable action refs, `permissions: write-all`, unsafe `pull_request_target` usage, inherited reusable workflow secrets, untrusted shell interpolation, remote installer pipes, Docker login password arguments, and unpinned global installs.
- Detects release workflow risks across package publishing, container publishing, GitHub Release creation, semantic-release, release-it, Changesets, PyPI trusted publishing, npm provenance, and manual publishing workflows.
- Checks for committed sensitive file names and missing `.env` coverage in `.gitignore`.
- Generates Markdown, JSON, and optional SARIF reports.
- Supports CI-oriented controls: `--fail-on`, `--quiet`, explicit `--config`, automatic report directory creation, and SARIF upload workflows.

## Install

```bash
npx oss-safe-release scan
```

```bash
pnpm test

pnpm run lint
node dist/src/cli.js scan . --markdown examples/self-scan-report.md --json examples/self-scan-report.json --sarif examples/self-scan-report.sarif --fail-on high
git diff --exit-code examples/self-scan-report.md examples/self-scan-report.json examples/self-scan-report.sarif
```

Expected self-scan result:

```text
oss-safe-release: no findings; scanned <file-count> files, <workflow-count> workflows, 3 rules
```

## Scope Notes

- This is a deterministic pre-flight scanner, not a complete security audit.
- This first release is GitHub-only unless npm ownership and package publishing details are explicitly approved later.
- No account identifiers, API keys, tokens, private emails, or OpenAI organization IDs are included in release artifacts.

## Follow-Up

Planned follow-up work includes additional release ecosystem rules, better source location tracking, richer SARIF metadata, and optional AI-assisted finding explanations after the deterministic scanner remains stable.
