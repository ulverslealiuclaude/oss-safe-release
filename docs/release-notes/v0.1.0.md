# oss-safe-release v0.1.0

`oss-safe-release` is a local-first CLI for open-source maintainers who want pre-flight checks before merging pull requests or cutting releases.

## Highlights

- Scans GitHub Actions workflows for mutable action refs, broad token permissions, unsafe `pull_request_target` usage, untrusted shell interpolation, remote installer pipes, and unpinned global tool installs.
- Scans release workflows for unsafe package, container, GitHub Release, semantic-release, release-it, and Changesets publishing patterns.
- Checks publishing workflows for explicit token permissions, GHCR `packages: write`, GitHub Release `contents: write`, npm provenance and PyPI trusted publishing `id-token: write`, npm token environment gates, and npm/PyPI token interpolation in shell commands.
- Scans repository files for committed sensitive file names and missing `.env` coverage in `.gitignore`.
- Produces Markdown, JSON, and SARIF reports, with SARIF rule metadata and result rule indexes for GitHub code scanning.
- Prints a console scan summary with finding counts, severity breakdown, scanned file count, workflow count, and built-in rule count.
- Includes GitHub Actions examples for CI gating, SARIF upload, and report artifacts.
- Supports config ignores with `oss-safe-release.config.json`.
- Supports CI failure thresholds with `--fail-on`.

## Verification

The release commit should be verified with:

```bash
pnpm test
pnpm run build
pnpm run lint
node dist/src/cli.js scan . --markdown examples/self-scan-report.md --json examples/self-scan-report.json --sarif examples/self-scan-report.sarif --fail-on high
git diff --exit-code examples/self-scan-report.md examples/self-scan-report.json examples/self-scan-report.sarif
```

Expected self-scan output:

```text
oss-safe-release: no findings; scanned <file-count> files, <workflow-count> workflows, 3 rules
```

## Scope Notes

- This release is GitHub-only unless npm ownership and publishing credentials are explicitly approved.
- No account identifiers, OpenAI organization IDs, private emails, API keys, tokens, or credentials should be included in release notes or artifacts.
- The scanner is a deterministic pre-flight tool, not a complete security audit.
